PR design review

Production self-hosted Agent Canvas on AKS

This change turns Canvas into a complete open-source, Entra-authenticated AKS deployment: the browser authenticates through a BFF, organization-scoped APIs run in Sandbox Server, and conversations launch into immutable Linux or Windows runtime profiles with private persistence and memory.

1Decision and review focus

Key decision: keep identity, organization state, and runtime ownership explicit. The BFF signs a short-lived internal assertion; Sandbox Server owns organization-scoped settings and workspace metadata; Kubernetes controllers own runtime resources. No browser credential becomes a runtime credential.

The highest-value review path is the trust boundary from getUpstreamIdentityHeaders() at scripts/entra-bff.mjs:605 into the organization boundary at CloudOrganizationBoundary at cloud-organization-boundary.tsx:15, then the selected sandbox profile into createWorkspaceRuntimeController() at workspace-runtime-controller.mjs:954.

Compatibility is additive for ordinary local Canvas users. Halo-specific behavior is activated by deployment configuration; shared frontend adapters retain local and cloud paths, while the Helm and Docker changes make the new services deployable.

6Risk and evidence

Primary risks: authentication claim mismatch, stale cross-repository image pins, database migration prerequisites, Windows node/image readiness, and shared frontend behavior across local and hosted modes.

Observed end-to-end result: the PPE deployment rolled out Canvas, Sandbox Server, Agent Server, Linux runtime, Windows Server 2025 runtime, PostgreSQL, and Hindsight by digest. The final live Sandbox Server was 1/1 Ready; migrations completed through revision 020; signed identity requests to /api/v1/users/me and /api/organizations returned HTTP 200.

Targeted verification: Halo deployment contracts passed 33/33. The unified Sandbox lineage passed 16 identity/RBAC tests, 5 migration tests including Alembic up/down/up, and 111 Kubernetes sandbox/service/spec tests in its owning repository.

Review note: this PR intentionally contains the Canvas-owned integration and deployment orchestration. Canonical SDK and Sandbox Server behavior remains pinned to exact commits in their owning repositories rather than copied into Canvas.
